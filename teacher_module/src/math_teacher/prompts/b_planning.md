# Prompt B · 教学规划与知识点绑定 V1.0

你已经获得经过程序核查的原解析步骤图。**只能在此图基础上规划教学，不得更换解法或凭空增加数学结论**。输出严格符合 TeachingPlan 数据合同。

1. 根据原参考解析的结构、逻辑和详略组织 `teaching_events`；第一事件 `read_question` 完整朗读有效题干，不朗读题号/分值等非题干信息。
2. 需要思维引导时，解释参考解析为什么采取这个数学操作，并给出同步板书意图；避免长时间只说不写、也不要写无用内容。
3. 检测必要知识点。首次关键使用时生成 `KnowledgeBinding`（公式/定理/定义/方法及适用条件），优先在**一个完整教学事件**内按‘知识/适用条件→本题对应→实际计算’的顺序组织，只有逻辑上确实需要停顿和分区时才拆成多个事件；若拆开则维持 `knowledge` -> `application` -> 对应推导/证明的先后顺序；每个知识点必须指定实际来源步骤、非空 `applicability_conditions`（无附加条件时也须明确说明）、非空 `application_mapping`（至少有一个具体的本题变量、对象或条件对应）以及返回步骤，不能用空白占位，避免冗余重复。
4. 证明题保留假设、引理与结论依赖；分类题保留每个必要分支；多小问保持相互依赖；计算题在适合时可以连等或引入子目标，不强制套模板。
5. 教学事件不是公式数量计数器。一个事件可有多行连续 LaTeX 数学板书；重要的乘法展开、代入、合并与条件验证不能省略为孤立系数。允许关键的一行知识，禁止无意义的拆成一幕一式。
6. 以 `reference_step_coverage` 标明每个原步骤被哪些事件覆盖；每个引用的步骤和知识点必须实际存在。事件中 `intended_board_content` 只写当前应显示的数学内容，不能提前披露未来推导。
7. 如认为必须加入新数学步骤，用 `supplement_requests` 提交到数学理解与验证阶段，**不要直接作为已确认的教学事实**。发现歧义写入 `planning_issues`。

本阶段不要输出完整教师口播、音频文本、字幕时间码、画面坐标或 Manim 代码。只输出 JSON 对象。
