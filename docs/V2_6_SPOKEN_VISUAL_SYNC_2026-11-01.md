# V2.6 口播—动态绘图—数学板书同步规范（2026-11-01）

## 本次真实视频缺陷

2026-11-01 对晓晓语音版本源 MP4 逐帧检查：原 5,495 帧（183.17 秒）的 6–8–10 直角三角形讲解，开场仅呈现 AB、AC 两条直角边；完整斜边 BC 到约第 50 秒才画出，而老师开场已经说“画出直角三角形”。图形动作每条线原仅约 0.72 秒，之后整段语音存在长时间静止画面。第二幕承接等式被机械重复完整朗读，叙述和新视觉信息不足。

本次缺陷不是视频帧率引起，不能通过直接提高整片倍速或仅调整字幕修复。

## 所有有声课堂必须遵守的长期规则

1. **每一条视觉承诺对应真实动作**：当教师说“画出图形”“连接两点”“标出直角/顶点”，相应的源验证对象必须在同一个口播动作内逐步出现。仅有完整教学段落或 JSON 宣称显示而实际帧没有出现，不能通过验收。
2. **内容与图元状态一致**：允许先画局部再补完整图形，但口播只能说已经画出的部分；若说“画完整三角形”，该动作必须包含 AB、AC、BC 三条边。结构来源 `diagram_classroom.json` 必须显示每个事件的 `reveal_ids`。
3. **真实口播决定实际画面时间**：以 Edge TTS PCM 测得的时长与 Manim 实际动作起止帧作为同步源；绘制应在所对应的语音片段中持续进行，避免在片段开头瞬间画完而剩余长时间静止。数学书写在讲到相应公式时开始，字幕仅来自真实已发声的短句。
4. **每个完整教学环节都有实际数学/图形进展**：可以有必要的教师说明，但不能长时间独白不推进画面；不得为了显得详细而重复讲整段数学表达式。思想引导、知识点和总结应在使用它们的教学事件出现。
5. **跨幕数学承接不等于重讲**：换板确需重写时，必须原样承接经验证的 MathTex 与源 ID；上一幕已经详细口述过的等式可以简短明确指出并继续计算，避免再次完整念出同一条证明。来源关系和可见公式必须不变。
6. **不以脚本/模拟动画代替实际验收**：新题与修改后题目必须审计 `event_timing`、`diagram_reveal_timing`、声画流、SRT、真实 MP4 解码帧和关键图元像素。缓存或音色更换时须重新验证时间轴。任何来源无法确认的渲染都应失败或回退，不可假称完成。

## 本次实现和证据

- `build_math_memory_triangle.py`：e_intro 经源审核先显示 AB/AC/BC，e_angle 再显示直角符号，e_rule 再显示 B、C 的 MathTex 图形标签。
- `build_spoken_triangle.py`：教师口播重新按实际可视对象写作，缩短重复说明，保持所有计算公式的数学来源。
- `persistent_chalkboard.py`：按源验证片段时长分配每个可见图元的真实 Manim 动画，逐对象记录 `diagram_reveal_timing`，不再固定 0.72 秒快速画完再空等。
- `test_spoken_classroom.py` 与 `v2-6-spoken-drawing-sync.yml`：新增整幅三角形首幕覆盖、讲稿紧凑和跨幕承接测试；真实 MP4 复核斜边中点像素，从未绘制时 0 到绘制后 36 个深色像素，核对出现时间段与真实 Edge TTS 动作。

真实晓晓视频 3,050 帧 / 30 FPS，约 101.67 秒（旧版 183.17 秒），减少约 44.5%，并非通过删除数学核心步骤。新的四类长数学视频回归仍成功。
