# 考研数学视频：统一教师讲解流程设计 V2.7（待确认，设计不等于开发）

日期：2026-11-01。基于已确认的真实课堂规则，以及 main fcee1887 和待合并修复 PR #34 的教学样例复核。**本文件为设计提案；不修改任何引擎源码、语音数据或测试视频。**

## 一、整体课堂结构

独立题目的默认教学顺序：

1. 开场与完整读题。
2. 思考引导（原名“思维引导”）：根据实际题目特征解释为什么采用相应解法。
3. 依据参考解析逐步求解；在真正需要的步骤附近穿插核心知识点和易错点。
4. 明确给出题目结果、证明结论或全部小问答案。
5. **结果之后**独立进行归纳总结：简要回顾本题解题思路、关键公式/方法、典型易错点，然后自然结束。

这是**教学语义顺序**，不是强制规定五个视频场景或每个阶段固定时长。知识点/易错点应在需要时穿插，不应被硬切成孤立的一幕，更不能为了凑标签机械重复。

## 二、各环节定义

### 开场读题

默认口播：“同学们大家好，我们先来看一下这道{题型}题。” 题型依据题干判断，如极限题、定积分题、微分方程题、矩阵题、证明题；不明确则称“这道题”，不胡乱判题型。可作有限自然措辞变化；连续多题不机械重复问候。

然后用真实课堂语言朗读**完整有效题干**：所有关键条件、定量、变量范围、图形约束、小问、选项和求解目标；不必朗读题号、分数和页码。数学符号在屏幕必须保持 LaTeX 正规书写，TTS 读音映射单独处理。题干从发声开始就可见，禁止先讲很多话而无对应板书。长题允许按小问/条件语义分段读，不能漏读。

### 思考引导

回答三件事：看到了什么数学结构？为什么选择这个方法？先从哪里入手？它是**解题思路**，不能用“接下来开始计算”“先化简”敷衍，也不在此阶段直接公布最终答案。与题目、必要图形或简短提示同步呈现，不能长时间空讲。

### 核心知识点

是本题在求解中真正用到的、可以迁移的**公式或方法**，还包括定义、性质和定理。必须解释使用条件、判断依据及在本题中的对应。首次关键使用时/紧邻之前自然穿插，能在同一个数学教学单元完成“知识→本题对应→计算”时不分幕。

- 有标准数学公式的：保留审核过的原 MathTex、适用条件与实际应用步骤映射。
- 以方法为核心的：允许方法知识点及清楚的识别依据，不强迫造一个无关的公式；方法若含数学表达式也可配真实公式。
- 不把移项、展开、普通代入、合并同类项、简单心算当成核心知识点。
- 不要求每一步或每个公式都有独立知识点，只有真正关键处才强调。

### 易错点

指学生**可能写错的具体位置**、典型错误及正确做法，必须绑定到真正有风险的步骤，在出错步骤之前/当下/紧接着说明。不能只说“注意不要错”；不能把所有易错点集中放在答案之后。若本题没有值得单独提示的典型错误，不强行创造一个。

### 正式解答

严格依照用户给定题干与参考解析及已核对的必要补步。该写的关键计算不跳步，简单计算不拆得琐碎。用数学因果自然连接：“因为……所以……”“这里可用……”“因此继续……”，禁止“移动到计算区”“切换下一幕”“其公式为”等制作界面语言。

老师讲到哪个公式、符号、几何对象或关键步骤，板书/动画就写到那里；不得提前整组显示。字幕只源于真实口播，未朗读的数学板书、标签、知识点标题不会成为字幕。旧墨迹在板书容纳时保持，长题才按教学事件安全换板；字号、颜色、公式居中、跨页依赖与图形避免重叠延续既有规范。

### 结果与归纳总结分开

计算完成先明确结果并覆盖所有小问/证明目标；**这叫结论，不叫归纳总结**，答案不加框。

之后的归纳总结用简短话语回顾“本题核心识别点/方法—关键公式或使用条件—应避免的典型错误”。对已经讲过的公式不强行逐字重复或重新抄完整解题步骤；无合适易错点不生造。归纳总结允许**纯口播 + 简短板书提示**，不强迫写一条新的 MathTex。总结是独立语义目的，但可以与末页最终结果共用画面。

## 三、真实课堂示意：定积分

原题 I=∫₀¹ 2x e^(x²) dx。

- 开场：“同学们大家好，我们先来看一下这道定积分题。题目要求计算从零到一，二乘 x 乘 e 的 x 平方次幂，对 x 积分。”（原题同步显示）
- 思路：“先看结构：指数里面是 x 平方，前面的二乘 x 刚好是内层函数的导数，因此考虑换元法，将它化为基础指数函数积分。”（对应结构高亮或简短数学提示）
- 知识点/应用：“这里用定积分换元法。令 u 等于 x 的平方，那么 d u 等于二乘 x d x。定积分换元时，积分限也必须改为新变量对应的值。”（逐步写出换元关系）
- 易错点：“不要只换被积函数、忘了积分上下限。本题恰好换元后仍是零到一，但这是重新代入所得，不是换元时可随意保留原限。”
- 推导：“变成从零到一对 e 的 u 次幂积分，原函数为 e 的 u 次幂。代入上下限，得到 e 减一。”（完整公式随语音写出）
- 结果：“所以本题的结果是 e 减一。”
- 回顾：“这题的关键是发现复合函数和内层导数同时出现，从而选换元法；最需要注意的是新变量的上下限也要同步调整。”

**这段是新版设计示范，绝不代表已经生成的旧 MP4 包含该讲解。** 更强的换元测试应选上、下限实际发生变化的题，而非只测值恰好不变的特例。

## 四、已有能力与缺口

| 项目 | 现有基础 | 需要更新的设计 |
| --- | --- | --- |
| 读题 | Teacher 的 B/C Prompt 明确要求读题；音频合同可绑定题干源 | 标准开场 + 题型准确 + 条件/小问的实际音频来源覆盖，不只检查布尔字段 |
| 思路 | classroom_cues 提供 strategy 类别 | 从读题后的数学特征推导方法理由；不能与首句读题或操作命令混淆 |
| 知识点 | 核验过的知识公式有 used_in；Teacher KnowledgeBinding 已含 method | 核心知识允许“公式**或**通用方法”；统一教师模块和动画编译的两种合同 |
| 易错点 | pitfall 配色、视觉标签已具备 | 绑定风险步骤、错误形式及纠正方法；在过程中就地穿插 |
| 结论 | final math result 可写出 | 结论阶段独立于后面的回顾阶段 |
| 回顾 | summary phase 存在 | 现有新题把最终答案直接标为 summary；应新增真实“答案之后的总结”语义，可无新数学公式 |
| 语义验收 | 现有校验偏重来源哈希、事件/动作覆盖 | 追踪完整“题干→思路→关键知识→步骤/风险→结论→回顾”及真实口播的语义覆盖 |

具体代码限制：classroom_teaching_units 当前强制每个教学单元有 1–6 条数学式，不能自然表达纯口播回顾；core_knowledge 当前要求 knowledge 必带公式且没有 method 类型，需在开发时设计方法与公式双通道；最新换元积分测试的首句不包含固定问候、实际 summary 为 I=e−1 而不是结果之后的知识回顾。

## 五、今后设计的数据合同（供开发时实现）

- 开场：problem_type、完整 source 条件/子问引用、真实读题短句与音频覆盖。
- 思路：observed_feature_refs、selected_method、why_applicable、planned_first_target。
- 知识点：kind={formula,theorem,definition,property,method}、适用条件、引用步骤、具体应用映射；数学式按需，禁止编造。
- 易错点：trigger_step_ids、typical_wrong_action、why_wrong、correct_action、实际口播/板书锚点。
- 解答：有序源步骤、对象 ID、公式/图形/口播短句与 PCM 对应；连续语义单元可有多行板书。
- 结论：全部题目目标和小问对应的最终结果，经过数学核验。
- 归纳：在结论之后出现的 review_takeaways，引用本题真实用过的知识/方法/易错点，允许无新增公式的口播教学事件。
- 验收：不能仅凭 event count、question_read_aloud=true、pedagogical_cue_covered=true 声称满足教学目标；自然过渡与总结必须独立由教师检视。

## 六、上线验收条件

至少用陌生极限题、上下限真正发生变化的积分题、带条件的证明题、矩阵题及多小问题验收，覆盖开头、读题、方法选择、核心知识穿插、真正的易错提醒、无跳步板书、最终结论及**其后的**小结。检查真实视频与实际 TTS/字幕、跨页换板、口播自然度；不能仅以 source JSON 通过或 MP4 成功作为课堂质量验收。

教学内容由 Gemini/教师层决定并审查；Codex 只在明确授权后实施结构化接口、引擎与音画测试。现阶段只批准设计评审，不进入实现或更改生产视频。


## 七、2026-11-01 采纳的 V2.7.1 强化提示词与执行检查（正式批准开发）

用户批准增加以下六条强制规范，继承上一节“不机械重复已讲过的公式、知识点按需强调”的边界：

1. **首幕完整忠实读题**：固定默认问候“同学们大家好，我们先来看一下这道{题型}题。”之后，按题目原始顺序朗读题目背景、全部有效条件、设问、小问与选项，不漏读、不擅自省略或改写数学事实；公式的屏幕 MathTex 与自然发音是不同表示，不能要求两者字节相等。必须核验逐段源题面与实际发声音频语义锚点；仅布尔 `question_read_aloud` 不可证明全文读完。
2. **逐项双向声画覆盖**：每条*新出现*的文字、公式行、图形标注及绘图动作均应具有可追溯口播，关键写入时序和实测语音重叠。长式分步、短式合理并列；不对已经读过且保留的旧墨迹反复机械朗读；禁止先整屏板书再统一念、或说出未来推导而不书写。
3. **知识点独立强调、讲完再应用**：真正关键公式、定理、性质、判定或可迁移方法必须具有独立识别标签、实际内容与口播说明，接着结合本题对象和条件应用，不能以“代入公式得到”跳过核心依据；在不涉及关键知识的普通运算不为凑数造公式。
4. **思路和风险适地穿插**：读题之后先解释题目结构、为什么想到对应方法。典型易错点必须明确“易错行为—出错原因—正确做法”并锚定真正的推导风险步骤，而不是空泛口号。优先保证数学主线完整。
5. **白板直接书写**：题干、选项、普通推导及核心知识点均直接写在白色课堂背景上，禁止装饰性文本框、答案边框或卡片；字幕与必要的 UI 辅助标签不受此限制。保留题干居中、MathTex、知识点独立颜色、字幕安全区和旧墨迹保留。
6. **先审核完整讲稿再允许渲染**：至少有原题完整源锚点、每句真实口播、对应文字/MathTex/图形动作、顺序、阶段、重要知识点及风险点、最终结果和其后独立的归纳总结。先导出机器可检查 JSON 和可读 Markdown；在 TTS 前拒绝缺知识点口播、缺新板书读音、无源读题或未闭合的结论/总结。真实 TTS/MP4 仍需另做音画时间轴和逐帧人工验收；代码不能自动保证语义质量。

**落地策略**：新课堂启用强制的 `V2.7` 教学讲稿合约（保留旧 `1.0` 文件兼容、但不为旧文件冒称满足新规范）。通过新题的实际独立事件检查：开场与全文读题、思路、知识点与应用、风险提示、结论、答案后总结。不得以 CSV/JSON 声明代替试听和关键帧检查。设计先行，代码在独立开发分支提交，不直接推送 main。
