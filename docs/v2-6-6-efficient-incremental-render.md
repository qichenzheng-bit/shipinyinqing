# V2.6.6 高性能渲染与增量微调引擎（工程说明）

本阶段在已经验收的 V2.6.5 之上开发，禁止改动原有的数学来源验证、真口播、音画同步、几何图生命周期以及仅对外输出最新 MP4 / 单一 JSON 历史的行为。**没有用户界面，也不要求观看旧版本。**

## 2.6.6.1 持久资源缓存与耗时分析

- 真正 Edge TTS 语音片段经测得的 PCM 校验后按文本、音色、语速、采样率、引擎源代码及依赖版本缓存。**不变的语音不再向 TTS 提交请求**，同一轮重复短句也可复用。
- MathTex 生成的字幕透明 PNG 复用。读取时必须完成真实解码，校验 1280×88 RGBA 画面与透明区域；损坏立即失效，绝不伪装为有效字幕。
- 每个完整分幕的 Manim 原始 MP4、来源审计、action timing 成组缓存；本模块不把渲染完的像素截图冒充可编辑公式。
- 缓存条目附带来源键、内容哈希、真实字节数。写入采用临时目录发布；不允许直接跳过来源验证。
- manifest 记录 speech, stage, subtitles, mux 阶段实际秒数以及本轮缓存命中。

## 2.6.6.2 实际差异与依赖失效

- 对比最新成功教学包与当前编辑包的 JSON，而非相信 AI 自报的影响范围；采用真实 event_id、stage_id、object_id。
- 语音局部变化：失效对应短句缓存和对应分幕视频，重新计算全局时间轴，但不自动失效其他独立分幕的画面。
- 变更全局音色/语言、布局清单或跨幕数学来源：扩大依赖影响范围，必要时全片重生成。
- 任何即使“看起来一样”但指纹不相符的资源均须重算；数学证明来源改动仍须独立审查。

## 2.6.6.3 可安全复用的增量渲染

- 原有两种引擎模式（普通 unified、几何图自适应 adaptive）都按分幕保存真实 Manim 视频和分幕动作时间。
- 未改变的分幕满足一致的 source/voice action timing/layout 等缓存键时，可直接复用视频；受影响分幕重新由 Manim 绘制。
- 尤其是 adaptive 模式，几何图 panel 的提取、保留、恢复和擦黑板效果仍按最新场景关系重新合成，不允许凭旧视觉截图跳过跨幕校验。
- 每轮最终字幕依据**实际 TTS PCM 和真实动画开始时间**重新计算。
- 对内部片段参数完全兼容的 H264 视频，优先经 ffprobe + ffmpeg 解码/帧数验证后进行无损码流复制拼接；无法验证或码流不兼容则回退到原来的编码方式。此优化只影响内部无声视频，不跳过最终语音和字幕的真实混流审计。
- 每次渲染仍输出唯一新的 latest.mp4；失败时保留上一轮成功作品。

**明确边界**：当前实现的是分幕级 Manim 视频复用 + 短语级 TTS 复用 + MathTex 字幕图像级复用。尚不能独立恢复“同一幕里任意一个数学对象动画”的 Manim 交互状态并仅渲染那几秒。要实现它需要独立的板书对象状态快照、进入/离开状态兼容性证明和事件级动画剪辑；不能将本阶段的分幕缓存说成任意事件级重渲染。

## 2.6.6.4 质量与性能双验收

- 单元验证：真实来源改变、全局音色变化、语音重复、缓存数据损坏、错误字幕透明度、场景时长改变、失败回退。
- 实际 FFmpeg 测试：两段同参数 H264 需可直接复制并精确保留总帧数；不兼容则重编码或报错，不发布错误视频。
- 真实有声验收：完整 1280×720 / 30fps、Edge TTS/MathTex，连续两轮修改，检查第二轮后两个不变分幕复用、其他分幕真实重做，以及整片音频和字幕覆盖。
- 第一次验收（未启用无损分幕拼接时）：181 秒的冷缓存编辑对比 130 秒的第二次热缓存编辑，约 1.39 倍、耗时降低 28.2%；其中两轮修改工作量不同，因此只是工程参考对照，**不是严格相同任务 A/B 性能基准**。
- 无损码流拼接优化后，须以最新 Actions 的实际报告为准，绝不提前宣称耗时减少 50% 或测试已通过。
- 不降低帧率、字体精度或课堂完整性。因依赖不明确而不能复用时，始终宁可完整重新渲染。

## 调用方式

在允许跨轮复用的同一个目录下启用独立持久缓存：

    math-animation render-spoken --spoken work/package/spoken_classroom.json --output work/lesson.mp4 --manifest work/lesson.json --srt work/lesson.srt --adaptive --fps 30 --cache-dir work/resource-cache

微调会话中的 edit-apply 会自动在会话目录维护 render_cache，仍保持 V2.6.5 的自然语言多要求、满意反馈和单一 JSON 导出契约。无需用户交互界面。
