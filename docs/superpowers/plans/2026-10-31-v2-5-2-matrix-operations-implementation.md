## 开发边界与基线

- 基线是上一阶段用户认可的 V2.5.1 最新视觉分支 `fix/v2-5-1-close-question-analysis-gap`，SHA `664d329a418e8715c6280c7a59532b3bf412947f`，并非只有 README 的 `main`。
- 继续遵循：白底、固定原始题干、黑色 MathTex 正文、知识/方法标题色彩区分，题干与解析紧凑、每个教学事件整体水平居中、写完不消失、不移动、满板只在完整教学单元边界擦除、底部为未来真实字幕保留安全区。
- 与积分的区别：矩阵必须显式保留**前态、初等行操作、后态**三者的顺序和同屏对照。不得把前一矩阵无解释直接替换成下一矩阵。矩阵和行列式不是普通公式的视觉字符串替换。
- 不接入 AI 自动解题、TTS 或声称“真实口播对齐”的字幕；此阶段的示例是单独编写且经数学验证的教师审核内容。

## 当前实现

### 严格数学合同：`animation_engine/src/animation_engine/matrix_steps.py`

矩阵阶段使用独立的 `--matrix-steps` JSON 合同，不复用 `--computation-groups`。其必选数据包含：
- `schema_version=1.0`，`mode=verified_matrix_operations`，`teacher_reviewed=true`，来源 `source_storyboard_sha256`；
- `kind`：`linear_system`、`inverse`、`determinant`；
- 原矩阵行数据、可选增广列界、严格有序的每一步 `before`、`operation`、`after` 数学源对象 ID 及其实际元素；
- 末步结果及有明确数学含义的非零假设。

每个变换在实际渲染前做双重核查：所有矩阵和标注必须严格对应真正的原始 source MathTex；其次使用独立 SymPy 行运算验证结果，而非信任动画补写的数值。线性方程组必须化为 `[I|x]` 且与原系统解一致；求逆必须化为 `[I|A^-1]` 且 `A` 可逆；行列式初版仅接受不会改变值的行加倍数变换，防止行交换或行缩放漏写因子。

参数由**只准四则运算、限制幂次和单字母参数**的 AST 白名单解析，不执行任意 Python 表达式。若某行除以 `a-1`，必须由教学源头提供 `a-1 != 0` 的明确假设；没有条件则拒绝渲染。零倍缩放、越界行号、改变矩阵形状、伪造矩阵元素、来源哈希失配、缺少 MathTex、插入未经批准的额外事件等也拒绝。

### 版式与动作：`persistent_chalkboard.py`

- 每一个行操作单元都按“**操作前矩阵 → 操作公式 → 操作后矩阵**”的有序 MathTex Write 生成；三者全部在画面上留存直至真实课堂式擦板。
- 先通过真实 MathTex 尺寸测量。宽度允许时三者左右相邻、整体居中；否则选择上一行展示前态+操作、下一行展示后态。装不下完整教学事件则明确拒绝，而不是偷偷删步骤、把字缩得过小或覆盖题干。
- 每次完整矩阵事件才允许换板；每个事件开头有来源可信的前态矩阵，所以翻页后不会从无依据的矩阵凭空开始。
- 与 V2.5.1 的积分 `computation_manifest` 严格互斥。没有 `matrix_manifest` 的矩阵场景依旧必须失败，防止“看似渲染成功却遗漏矩阵语义”。

### 三套不重复的全新数学题

- **A 连续消元**：3×3 线性方程组 7 次初等行变换，完整增广矩阵演算，得到 `x=1,y=2,z=3`。
- **B 逆矩阵**：2×2 矩阵与单位阵组成 `[A|I]`，经 2 次明确操作得到 `[I|A^{-1}]`，求得 `[[1,-1],[-1,2]]`。
- **C 含参数行列式**：`[[1,1],[1,a]]` 的第二行减去第一行，行列式不变得到 `D=a-1`，同时写出 `a=1` 与 `a!=1` 的两类结论。

三个题均通过独立源文件 `animation_engine/tools/build_matrix_classroom_lesson.py` 生成，分别导出原题、教学单元、StoryboardPlan、ExecutionPlan、知识/方法提示、matrix_steps.json、课堂 policy。

## 后续细化，不能冒充已完成

- 本次先实现**数学意义可信的前后矩阵对照及操作标注**；矩阵单个元素或指定行的瞬时蓝色高亮需要未来的元素级 MathTex 子对象绑定及防重叠动画，不能用对整块矩阵画一个不对应的荧光框来伪装已经实现。
- 分块大矩阵、列变换、交换行列式符号与行缩放的行列式因子、秩的分情况讨论、更多自由参数与参数化解集，需要在更多专属合同与验证用例完善后逐项扩展。
