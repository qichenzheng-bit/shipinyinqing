# V2.5.3 长证明、引理承接与分类讨论课堂开发

## 已确认的课堂标准

承接 V2.5.2 最新已验收代码与用户确认的视觉规则：白板、固定顶部题干、题干与解析紧凑、每个教学单元整体水平居中、真正 MathTex 和黑色正文；教师思维引导/知识点/易错点/总结使用已固定的分类色彩；写出的数学对象保留至整板写满才擦，换板必须保留后续依赖的来源可信的条件、待证目标和已证明结论。题目结论不要加答案框。底部字幕安全区仍预留，尚无音轨不显示虚构对齐字幕。

证明内容必须忠实教师给出的已审核解法。讲清关键依据，不无意义逐字符拆分；数学引擎只执行源步骤，不猜测证法，也不凭空补充分支。

## 本轮数学证明来源合同

新增独立 proof_chain.py：由教师审定的 JSON 包含 anchors、stages、branch_groups、来源 SHA256 和 teacher_reviewed 标志。

- anchors 必须在首事件写出条件和证明目标，目标不是自动已证结论。
- stages 明确列出完整有序的 setup / derivation / lemma / case / merge / conclusion，每阶段包含实际源 MathTex 对象、所引用的此前对象、跨页必须承接的对象，以及是否允许在该阶段结束后安全擦板。
- 所有证明对象均只许从已审批 Storyboard/Execution 引用，不能跳过阶段、提前引用未来引理或删除写过的数学。
- 整板确实写满且上一阶段允许安全换板时，下一页重新书写已知条件、待证目标及当前所需引理。继承对象放不下则明确失败，不删证明步骤、不挤占题干/字幕、不无下限缩小字号。
- 分类讨论必须显式列出所有情形，下一步 merge 必须逐一引用每种情形的末结论，禁止在未合并前跨互斥情形错误引用对方的结论。
- 专属合同与 V2.5.1 积分及 V2.5.2 矩阵合同互斥。只有合法 proof manifest 才允许专属 proof_scroll 版式进入持续书写引擎。
- 本阶段自动检查的是证明来源、引用图和分类覆盖，不等于完整形式化证明；关键数学恒等式由独立符号测试验算，最终仍需人工数学审核。

## 首版三道全新题

A：立方和恒等式的数学归纳法。明确起点、归纳假设、下一项展开、提取公因式、关键代数引理、得到下一整数的正确形式后，最后总结对所有正整数成立。共 8 个教学目标。

B：对所有实数的三元平方和不等式及等号条件。计算右边减左边，把表达式改写为三个平方和，从非负性推出不等式，单独说明等号何时成立。共 7 个教学目标。

C：含参数二次函数对全体实数非负。配方并取 x=a 找必要条件；再完整讨论 a²<1、a²=1、a²>1 三种情形，各自证明成立或不成立，合并后得到 -1≤a≤1。共 8 个教学目标，1 个三分支组。

## 2026-10-31 二次修订：核心知识点必须是公式、定理或性质，绝非简化说明

根据用户明确反馈，修复首版错把局部推导写作“核心知识点”的结构化标签。数学归纳法原题的“写出归纳假设”“括号通分”改归解析过程；不等式题的“构造差值”“改写平方和”改归解析过程；参数二次式的“先配方”改归解析过程。

每道证明题新增独立的、完整的标准知识点及真实 MathTex：
- 归纳法：起点 P(1)，递推 P(k) 推出 P(k+1)，由数学归纳法对所有正整数成立；实际证明中的归纳假设依旧写在随后解析里，不能替换定理陈述。
- 不等式：任意实数平方和非负及其等号成立条件；然后应用到构造出的三个平方差，而非把差值构造本身称为核心知识点。
- 二次函数：开口向上的顶点式以及最小值在顶点取得的性质；随后按实际二次式配方、取顶点参数及完成三种情形讨论。
- 分类/证明下文显式引用前面已经展示的知识点公式，分页时仍通过可信源对象承接；不压缩字体、不打断计算原有步序。

编译时严格实行 `core_knowledge.py` 的单独知识点审核目录，包括可迁移的名称、类别、真实公式及实际应用事件。V2.5.1、V2.5.2、旧 ODE 演示已同步梳理并进行相同合同测试。真实 Manim 验收必须抽取核心知识点出现的画面，并检查它是否为数学公式而不是操作口令。
